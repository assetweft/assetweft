# AssetWeft 开发规范：DDD × Ports & Adapters

适用：新代码与被本次迁移实际触及的代码。现有违规按迁移批次收口，不追溯宣称旧代码已符合。产品能力与入口索引以[仓库导航](../README.md)与[能力地图](FEATURE_MAP.md)为准，各限界上下文规则以所属 `CONTRACT.md`（见[仓库导航](../README.md)）及[交付合同](../contracts/README.md)为准；本文件管实现约定，CI/验证与安全门禁引用[验证入口](../tools/verify.sh)与[C1 工作流](../.github/workflows/c1.yml)，不维护第二套检查清单。

## 1. 按领域组织，按内外边界写代码

- 先定位上下文、用例、聚合不变量、数据写者及直接消费者，再修改。技术目录名不决定业务所有权；每张表只有一个写入所有者。
- `domain` 仅含实体、值对象、状态转换和纯策略。禁止导入UI、CLI、rusqlite、HTTP/引擎SDK、进程启动或文件系统I/O；不依赖 `application`。
- `application` 编排用例，依赖领域与自己需要的出站端口；禁止调用具体SQLite/提供者/引擎适配器。跨上下文经公开业务API或组合根注入的端口，不导入对方私有仓储。
- `adapters` 将外部DTO、SQL行、路径/流、工具状态和错误翻译成核心语义；不得重新实现预算、版本覆盖或接受规则。
- `bootstrap` / 组合根构造连接、适配器和用例，控制生命周期；禁止夹带“失败算成功”“换提供者继续扣费”等业务策略。
- 迁移期 `Application` 可暂作既有连接/用例的兼容外观；新抽出的纯用例不可继续依赖该具体外观或从它取 Connection。暂存耦合列在所属 `CONTRACT.md` 的未迁移项中，不改名掩盖。

## 2. Rust 类型、可见性与模块合同

- 模块仅导出消费者真正需要的命令、查询、结果和稳定类型；内部适配器默认私有或 `pub(crate)`。旧路径通过明确 re-export/外观过渡，调用方迁完再删，不突然改 wire 或退出码。
- 对会混用的身份/修订/金额使用明确类型；金额、单位、币种、精度和 `unknown` 分别表达，不用浮点金额或0填未知。不为纯展示字符串制造大量无行为包装。
- 聚合入口守业务不变量；输入适配器守格式、大小、路径/权限等信任边界。内部可信调用不层层重复解析、容错、重试或大小写/空白归一化；既有逐字匹配契约继续生效。
- 领域状态使用受限枚举与显式转换，拒绝不支持状态。执行/质量/评价/费用不能共用一个 `success: bool`；`UNKNOWN/NOT_RUN/PARTIAL` 保留。
- 去注释化（对齐 `[细则·开发流程]` v25.6 §1）：废除强制文件头依赖/调用清单（`//! Responsibility:/Dependencies:/Callers:/Invariants:`）与注释覆盖率门禁，由代码索引、脚本依赖图与 CI 四维架构闸替代。禁止复述代码的注释与源码内 `workaround` 注释（临时补丁统一入 `review/p2` 缓冲池）；仅保留极少数类型无法表达的外部硬约束「Why」注释（外部 API/SDK 缺陷、法规/计费口径、并发顺序），且须挂 ADR、规范条款或 Issue 编号。模块 `CONTRACT.md` 记录实际公开API、表写者、关键语义、事务/锁顺序、消费者、未实现项；不复制跨域总纲，不预建空模块/空接口注册表。
- 不为“DDD风格”引入继承式实体基类、通用仓储、万能服务或DI框架。沿用锁定依赖与同步执行形态；新增框架、驱动、异步运行时需要具体消费者和独立选型依据。

## 3. 端口按业务目的定义

- 入站端口是用例能力，可为普通 Rust 方法，不强制每个入口对应 trait。CLI/桌面/Agent映射到同一用例，业务规则唯一。
- 出站端口由核心的实际需求定义，通常放所属上下文 `application/ports`；参数与结果为领域/应用类型，不包含 `rusqlite::Connection/Transaction/Row`、SQL影响行数、HTTP客户端或外部进程句柄。
- trait 只放真实能力，不镜像数据库每张表所有CRUD；不因每个函数都“可替换”而创建端口。使用静态泛型或少量 `dyn` 按实际装配需求决定，不预建动态插件系统。
- `current(&Connection, ...)`、`advance(&Transaction, ...)` 是具体SQLite适配器内部API，不能称为已隔离的应用端口。适配器之间借用同一事务是允许且必要的内部协作。
- 接受候选用专用 `CommitAcceptance` 能力，返回 Accepted/Conflict/已有回执或明确错误；应用不看SQL行数或负责提交连接。Catalog不依赖Production的Acceptance类型；跨域翻译由组合适配器承担。
- 凭据只传官方/系统存储的引用；外部适配器拥有具体解析与权限执行。核心协议不是对任意Shell Agent的万能安全边界。

## 4. SQL、对象、锁与迁移

- SQL仅放持久化适配器/迁移；参数绑定与类型化行映射，不拼接外部输入。不让CLI/UI拿连接，不把数据库或厂商错误类型穿透到核心端口。
- 领域规则在核心保持可测试；数据库约束/条件UPDATE作为实际并发与持久化保证。不能为了“纯领域”把原子预约或条件提交退回check-then-act。
- 固定先storage lease、后SQLite写事务；事务内禁止等待推理、HTTP、渲染或反向取lease。共享连接/事务仅在适配器内部有界使用。
- 头指针CAS与接受尝试回执在同一IMMEDIATE事务，保存旧回执幂等语义；冲突保留候选。写事务失败可能已发生副作用时返回不确定状态并查询，不自动重放写入。
- CAS先有界写/校验/不可覆盖发布，再短事务登记；元数据 `UNKNOWN/MISSING` 不等于字节就绪。新增引用、GC、备份共同遵守保留协议，不能仅让回收者上锁。
- 已应用SQL迁移文件不得改写；所有迁移号由统一迁移链协调，各域拥有其迁移内容。目录变化不重置schema、不批量改表名。应用/传输/SQLite/未来云端版本相互独立。
- 复用实际SQL/真实临时文件数据库验证参数、约束、回滚和竞争。当前rusqlite查询未全具编译期验证，文档不得声称已具备；是否补代码生成按真实收益另定。

## 5. 错误、取消与外部副作用

- 领域拒绝、应用冲突/不支持/未运行、适配器IO/数据库失败分别建模。适配器保留可诊断信息但对端口映射为稳定语义；输入适配器再映射到[既有wire/退出码](../crates/assetweft-cli/README.md)与[合同错误语义](../contracts/README.md)，不自造第二套码表。
- 调用ID与请求摘要固定、相同身份不同请求拒绝；已提交后响应丢失先查询。状态不明不是失败重试许可。
- 区分“未调用”“可能已调用”“已观察结果”“本地记录失败”；返回执行结果不能掩盖记录失败。客户端取消不代表提供者已停止或免单。
- 日志不含密钥、凭据URL、Cookie、完整私有素材或不必要提示词；公共协议不用本机绝对路径。记录源码/配置版本、作用域和产物引用，不伪造费用/性能/已运行状态。
- 输入不可信；文件限额/路径/下载授权检查放实际边界。保留原能力不足与权限门禁，不因换adapter放开任意命令、外传或付费。

## 6. 测试按边界分配

| 被验证对象 | 最小证据 | 不能替代什么 |
|---|---|---|
| 领域策略/状态机 | 确定性输入输出、合法及非法转换 | 提供者授权/真实资产质量 |
| 应用编排 | 经入站用例驱动，必要时用端口替身验证顺序/不确定态 | 真SQL、并发锁或真实提供者行为 |
| SQLite/CAS适配 | 真文件库、生产SQL、约束/回滚、实际重叠竞争与保留语义 | Mock数据不能证明事务/恢复 |
| CLI/桌面/Agent适配 | 受影响入口的真实协议/退出码/调用绑定 | 纯核心测试不能证明入口正确 |
| Provider/引擎适配 | 固定工具/环境/输入的原始回执与产物 | fixture不冒充F0/AI/三引擎 |

依影响复用现有检查；不为重构另建测试平台或数量目标。旧行为、回归和未知态断言不能删弱；没有具体变化/失败就不重复全量跑。修bug先真实红；新自动gate须注错红→修绿；未编译的失败不是行为RED。完整构建/全测默认CI，本地仅必要定向并落外接盘；具体CI/PR/审查/资源与安全规则按[C1 工作流](../.github/workflows/c1.yml)、[合同门禁](../.github/workflows/contracts.yml)及当前任务契约，不在此再造流程。

## 7. 迁移期执行与完成口径

每批先确认实际主线与相关契约，列唯一边界变化/兼容消费者/表写者和恢复方式，迁移真实用例后用当前SHA证据交付。先扩端口/兼容调用，再收旧路径；跨上下文语义变化先审契约。现行实现（取样 `14ff38bf76ab762e88afcc6f27582b2a4123c0df`，tree `6161a5479e323c1108716045cf94db417c87a16f`）已完成五个上下文业务用例与端口分离，落地了单库原子 `CommitAcceptance` 适配器，并在 Application 维持 SAME 公开兼容。旧 D1.1 仅移头类型且离线缺 rusqlite 未编译属于 2026-11-13 历史失败候选；当前代码范围已达 postCI202 与独立源码复核，最终集成状态仅以主控画布与最终导出回执为准；产品级范围（F0 暂无、三引擎等）维持 NOT_RUN / 未验收。

架构边界由 CI 确定性四维架构闸（`HEX-LAYER` 分层 0 违规、`HEX-CONTEXT` 允许边白名单 + DAG 无环、`HEX-WRITER` 15 张表唯一逻辑写主、`HEX-COVERAGE` 全文件归属扫描）与带修法指引的去注释/禁 workaround Lint 守门（未接入 PR 前以代码索引/实际 imports/独立复核核对，不提前宣称 CI 已自动证明）。新接入任何机器检查须留「注错变红→撤回变绿→全仓扫描零误伤」实测证据。

本轮规范不修改任何产品wire、锁定条款、SQL schema或真实授权；DDD/六边形是实现组织方式，不能降低原来的行为和产品验收标准。
